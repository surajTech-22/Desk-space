# R262 — explicit recent documents per pinned application

DeskSpace already had R122's default left-click action that looks for a matching Windows Recent shortcut and opens the most recent document with the registered default application. R262 **retains that behavior** and adds a second, explicit choice: **right-click a pinned application sector** to open a per-app Recent Documents picker. The picker scans at most 70 Windows Recent shortcuts on that user action only, uses the same Windows registered handler matching, deduplicates document paths, and presents at most ten matches ordered by shortcut usage date. It shows document base names and dates, not their full path, without opening or parsing document contents during discovery.

Only safe allowlisted document extensions are selectable, and an existing non-reparse document and same handler are rechecked at selection time. No executable, script, `.lnk`, `.url`, `.msi` or `.cmd` is offered as a recent *document*. The button **Open pinned app only** is also available. There is no automatic execution, new watcher, global history, settings mutation or telemetry in the new chooser. Existing cached single-latest app action is not read or written by the picker.

Windows native tests use disposable safe and script files to verify exact executable-handler match, date ordering, deduplication, a 10-item bound, and no data modifications; the empty-state WPF dialog is also checked. Real Windows Recent COM shortcut resolution, physical monitor positioning and application-specific launch behavior still require installed-PC acceptance before Stable and Tester release.
